# The reference for Idrak.Audio (plan 21, phase S0)

Written by `tools/audio/make_tiny_audio.py` (nothing downloaded); the versions are in `manifest.json`, with every
file's size and SHA-256. Two runs write the same bytes on the same machine and library versions; other machines or
versions may differ in the last bits of the torch outputs (the WAV files and their samples are exact everywhere).

| Folder | What |
|---|---|
| `wav/` | generated signals (1.5 s: a 440 Hz tone sweeping to 880 Hz with a seeded noise burst; a second channel of a 660 Hz tone with a later, quieter burst) as `pcm8`, `pcm16`, `pcm24`, `pcm32`, `float32`, `float64` (mono), `stereo16`, `extensible16` (WAVE_FORMAT_EXTENSIBLE, stereo, channel mask), `list-chunk16` (a LIST/INFO chunk of odd size before `data`), `rate8k`, `rate44k` (the signal generated at those rates), `oversized16` (a `data` chunk claiming twice the samples the file holds); each with its decoded samples as `.npy` (float32, `[channels, samples]`: PCM as integer / 2^(bits-1), float as stored) and `files.json` (rate, channels, samples); `bad-truncated.wav` (cut inside the fmt chunk) and `bad-no-fmt.wav` (no fmt chunk) for the refusals |
| `flac/` | the same signal written by libFLAC (through soundfile) as `pcm16` (the default level), `fixed16` (level 0: fixed predictors only), `lpc16` (level 8: LPC up to order 12), `stereo16` (the stereo pairs), `pcm8`, `pcm24`, `rate44k`, `mixed16` (stereo: silence, full-scale noise, then the signal: constant and verbatim subframes) and `wasted16` (every sample a multiple of 4: wasted bits); each with its integers as floats in `.npy` (integer / 2^(bits-1)) and `files.json` (rate, channels, samples, bits); `bad-truncated.flac` (cut inside a frame) and `bad-crc.flac` (a byte of the first frame flipped) |
| `mp3/` | the same signal through ffmpeg: LAME (`lame-*`: MPEG-1 44.1, 48 and 32 kHz, MPEG-2 22.05, 24 and 16 kHz, MPEG-2.5 8, 11.025 and 12 kHz; mono, plain and joint stereo; CBR and VBR; `lame-notag44k` without a Xing tag), shine (`shine*`), `tagged44k` (ID3v2 and ID3v1), ffmpeg's Layer II (`mp2-*.mp2`); each with ffmpeg's decoding (gapless) as float32 `[channels, samples]` in `.npy`, which mpg123 agreed with when it was made, and `files.json`; `bad-truncated.mp3` (cut inside a frame) |
| `mp3enc/` | written by `tools/audio/make_mp3_encoder_fixture.cs` (not by `make_tiny_audio.py`, not in `manifest.json`): the MP3 plug-in's encoder on `wav/` signals (`pcm16`, `stereo16`, `rate44k`; `rate44k` also with a second channel of its samples reversed and halved, and labelled 48, 32, 22.05 or 24 kHz, exactly), ten files over the six rates, joint, plain and mixed-down stereo, 32 to 320 kbit/s and the three qualities, each decoded by ffmpeg without an error; `files.json` holds the options, each file's SHA-256, ffmpeg's length, its SNR against the signal after the 1057-sample delay and the RMS of each channel's 576-sample blocks as ffmpeg decodes them |
| `resample/` | `rate44k.wav` and `rate8k.wav` resampled to 16 kHz by `torchaudio.functional.resample(lowpass_filter_width=6, rolloff=0.99, resampling_method="sinc_interp_hann")`, and `resample.json` with the parameters and lengths |
| `features/` | for `pcm16.wav` (16 kHz already): `stft-magnitude.npy` (`torch.stft`, n_fft 400, hop 160, periodic Hann, centred, reflect padding, the magnitude `[201, frames]`), `mel-filterbank.npy` (`torchaudio.functional.melscale_fbanks(201, 0, 8000, 80, 16000, norm="slaney", mel_scale="slaney")`, `[201, 80]`), `log-mel.npy` (transformers' `WhisperFeatureExtractor` on the 30 s padded segment: power, mel, log10 clamped at 1e-10, floored at max - 8, (x + 4) / 4; `[80, 3000]`), `features.json` with every parameter |
| `tiny-whisper/` | a `WhisperForConditionalGeneration` (d_model 32, 2 + 2 layers, 4 heads, feed-forward 64, 80 mels, 1500 source and 448 target positions, vocabulary 600) with weights from a seeded generator (normal, std 0.5: at 0.02 the tied head repeats its last input token and every decoding gives one token over and over; norms 1, biases 0), `save_pretrained` with `preprocessor_config.json`; `tokenizer.json` (a byte-level BPE trained here on the corpus, unused tokens filling to the vocabulary, then the specials `<\|endoftext\|>`, `<\|startoftranscript\|>`, `<\|en\|>`, `<\|ar\|>`, `<\|translate\|>`, `<\|transcribe\|>`, `<\|notimestamps\|>` and 31 timestamp tokens `<\|0.00\|>` to `<\|0.60\|>`; their ids in `special_tokens.json`), `generation_config.json` (the start, language, task and no-timestamps ids, the end token suppressed first, `max_initial_timestamp_index` 5); `reference/`: `encoder-output.npy` for `features/log-mel.npy`, `logits-step1.npy` for the prompt `<\|startoftranscript\|><\|ar\|><\|transcribe\|><\|notimestamps\|>`, `language.json` (the language tokens' logits after `<\|startoftranscript\|>` and the one detected), and 12 new tokens each from transformers' plain `generate` with Whisper's processors passed in (the suppressed first tokens; with timestamps, `WhisperTimeStampLogitsProcessor`): `greedy-ids.json`, `beam4-ids.json` (a beam of 4, length penalty 1, early stopping), `timestamps-ids.json` and `timestamps-beam4-ids.json` (from the prompt without `<\|notimestamps\|>`) |
| `ctc/` | the IdrakAudio plug-in's "ctc" network written in torch (plan 21, S6): two Conv2d (1, 3) stride (1, 2) over time with the 80 mels as channels and the tanh GELU (outputs past an utterance's frames zeroed), sinusoidal positions, two pre-norm blocks (4 heads, width 32, feed-forward 64) whose attention sees each utterance's own steps (key padding), a final LayerNorm and a head to 40 classes, blank 0. `model/` (seed 2029) and `model-conv/` (seed 2031, a Conformer-style convolution module between attention and feed-forward: pointwise to 2·width, GLU, padding zeroed, depthwise (1, 5), LayerNorm, SiLU, pointwise), each with `config.json` in the plug-in's keys, `model.safetensors` (the plug-in's names, torch's layouts), `tensors.json` and a 39-character `tokenizer.json` (token i is label i + 1). Weights at 1/√fan-in and biases and norms drawn (not zeros and ones), so every tensor's gradient carries information (per-tensor largest 0.25 to 4.7). `mels.npy`: 4 utterances of 96, 71, 123 and 50 frames padded to 123 with zeros (24, 18, 31 and 13 steps after the subsampling). `reference/`: `loss.json` (the labels, `ctc_loss` mean with zero_infinity at step 1 for both models, each utterance's loss, and `model/`'s losses after each of 3 SGD steps at rate 0.1: 22.07, 3.65, 3.31, 3.24), `grads-step1.safetensors`, `grads-step1-conv.safetensors`, `weights-step3.safetensors`, `logp-step1.npy` (`model/`'s step-1 log-probabilities [4, 31, 40]) and `alignment.json` (torchaudio's `forced_align` of each utterance's steps of `logp-step1.npy`, with each path's log-probability) |
| `tiny-vits-speakers/`, `tiny-vits-speakers-det/` | `--sections vits-speakers`: `tiny-vits/`'s sizes with three speakers and an 8-wide speaker embedding (`embed_speaker` at std 1 and the speaker conditioning layers at std 0.3, so the speakers sound different), the stochastic and the deterministic duration predictor (seeds 2041, 2042); `speakers.json` names them p225, p226, p227; `reference/waveform-K.npy` for the ids of "abc ab" as speaker K, noise 0 |
| `tiny-vits/` | a `VitsModel` (hidden 32, 2 layers, 2 heads, feed-forward 64, flow size 32, 1 prior flow, 2 WaveNet layers, upsample rates [4, 4] with kernels [8, 8], one residual block of kernel 3 and dilations [1, 3], 65 spectrogram bins, hop 16, no speaker embedding; seed 2030), a 20-symbol `vocab.json`; `reference/waveform.npy` and `input.json` for the ids of "abc ab" with `noise_scale 0` and `noise_scale_duration 0` (deterministic) |
| `tiny-openvoice/` | an OpenVoice tone colour converter from OpenVoice's own model code (openvoice-cli's `SynthesizerTrn`, n_speakers 0: the reference encoder, a posterior encoder of 16 WaveNet layers, 4 couplings of 4 layers, a HiFi-GAN decoder; inter 8, hidden 16, embedding 16, upsample rates [4, 4] with kernels [8, 8], one residual block of kernel 3; FFT 64, hop 16 at 16 kHz; weights seeded 2031 at std 0.2), `model.safetensors` with weight norm's `weight_g`/`weight_v` as stored and OpenVoice's `config.json` (`_version_` v2, `zero_g` true); `reference/`: the spectrogram of wav/pcm16 [33, 1500], the embeddings of it, of the second channel of wav/stereo16 and of that channel's second half, and of both (their mean), and its conversion to them with tau 0 for v2 (`converted-v2.npy`) and with `zero_g` off (`converted-v1.npy`) |
| `vits-train/` | fine-tuning VITS (plan 21, S9 route C): `model/`, a `VitsModel` (hidden 16, 2 layers, 2 heads, window 2, flow size 8, 2 prior flows of 2 WaveNet layers at dilation rate 2, 2 posterior WaveNet layers, upsample rates [4, 4] with kernels [8, 8], residual blocks of kernels 3 and 5, 65 bins, hop 16, 2 duration flows of 6 bins; seed 2041) with its decoder weight-normed (a training checkpoint's layout), weights at 1/sqrt(fan-in), `vocab.json`, and tiny weight-normed discriminators (`discriminator.safetensors`, `discriminator.json`: periods 2 and 3, two pooled scales; seed 2042); `audio-{0,1}.npy` (two utterances of 20 and 28 frames); `reference/`: VITS's spectrograms, the draws of three steps (`draws.safetensors`: the posterior's and the duration posterior's noise; the segments' starts in `steps.json`), step 1's alignment scores (`neg-cent-*.npy`) and paths, the discriminators' and the generator's gradients of step 1, three SGD steps' losses (and their terms) and both models' weights after them |
| `transcripts/` | `train.jsonl` of `{"audio", "text"}` rows over the fixture's files and `train-sharegpt.jsonl` (the same as ShareGPT with an `<audio>` marker and an `"audios"` list) |

## How the C# tests read it

- `"audio codecs:"` (S1): every `wav/` file decodes to its `.npy` (PCM exact, float within 1e-6); the header from the
  first bytes; `oversized16` decodes what the file holds; the two bad files are refused naming the file.
- `"audio codecs: mp3 encode:"`: the encoder writes every `mp3enc/` file again byte for byte (if a change is meant,
  regenerate with `dotnet run tools/audio/make_mp3_encoder_fixture.cs -c Release --no-cache`, which needs ffmpeg), and
  the plug-in decodes each to ffmpeg's length, its SNR within 0.01 dB and its block RMS within 1e-4.
- `"audio features:"` (S2): resampled samples within 1e-5; STFT magnitudes and log-mel within 1e-4 of the largest value.
- `"audio asr:"` (S4): the encoder output and the step-1 logits within 1e-4; the greedy, beam and timestamp ids exact.
- `"audio train:"` (S6): `CtcAlignment.Viterbi` on `logp-step1.npy` gives `alignment.json` exactly (its log-probability within 1e-4); the plug-in's step-1 loss within 1e-4 and every tensor's gradient within 1e-4 of that tensor's largest, for both models; the three SGD steps' losses within 1e-4.
- `"audio tts:"` (S5): the waveform within 1e-4.
- `"audio processing: filters:"` (plan 31, P1): `filters/`, written by `tools/audio/make_audio_filters.py` (numpy, scipy):
  each filter's output (scipy's `sosfilt` started settled on the first sample, RBJ's formulas, iirnotch, torchaudio's
  windowed-sinc resampler in float64) within 1e-5, chains rounded to float32 between steps as Idrak does.
- `"audio processing: repair:"` (plan 31, P3): `repair/`, written by `tools/audio/make_audio_repair.py` (numpy, scipy):
  each stage (denoise-live, spectral-gate, declick, declip, deess, dereverb) within 1e-5 of the script's frame-by-frame
  equations, and each effect (noise in the pauses, clicks, clipped samples, sibilance, late reverb) past its margin.
- `"audio processing: dynamics:"` (plan 31, P2): `dynamics/`, written by `tools/audio/make_audio_dynamics.py` (numpy, scipy,
  pyloudnorm): each live stage's output (gate, compress, limit, agc, loudness-live) within 1e-5 of the script's
  sample-by-sample equations, the integrated loudness within 0.01 LU of pyloudnorm, each whole-recording gain exact.

## Regenerate

```
python -m venv audio && audio/bin/pip install torch torchaudio transformers tokenizers safetensors numpy soundfile (and ffmpeg with libmp3lame and libshine for --sections mp3)
audio/bin/python tools/audio/make_tiny_audio.py tests/Idrak.Tests/data/audio
```

`--sections wav` writes the WAV files alone with numpy only.
