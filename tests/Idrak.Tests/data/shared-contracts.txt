# Contracts kept in Idrak.Abstraction because any package can use them (CLAUDE.md: a contract any package can use, now
# or later, lives in Idrak.Abstraction), though one package uses them today. Decision 10
# (tests/Idrak.Tests/InventoryTests.cs) keeps them there; once several packages use one, its line is refused as stale,
# so the list only shrinks.
# contract | why
Idrak.Abstraction.Generation.ITokenSampler | any model that generates tokens step by step samples them the same way, whatever the tokens stand for (text, speech, images)
Idrak.Abstraction.Generation.TokenSamplers | the sampler every token-generating package takes, overridable once for all of them
Idrak.Abstraction.Retrieval.IVectorStore | embeddings of any kind (text, images, audio) are stored and searched the same way
Idrak.Abstraction.Generation.IImagePositionRule | how a vision-language family's image tokens sit on a multi-axis rotary embedding: the decoder (core) applies it, a family plug-in or an app may give its own, and a tuner or server placing tokens itself reads it
Idrak.Abstraction.Generation.ImagePositionRules | the position rules by name, beside ImageAttentionRules, overridable once for every package that places image tokens
Idrak.Abstraction.Data.IOutlineRasterizer | how glyph and shape outlines become pixels, for every package that draws text or shapes (Imaging, Text's synthetic pages, Vision's synthetic samples)
Idrak.Abstraction.Data.OutlineRasterizers | the outline rasterizers by name, overridable once for every package that draws outlines
Idrak.Abstraction.Data.IOutlineTracer | how a glyph's ink becomes its outline, for every package that makes fonts from images: Imaging's contour tracer today, the glyph sources that find glyphs on a page (Vision, plan 38's F2 and F4) and the command line's font-from (F6) next, and an app's or a plug-in's own tracer over the library's
Idrak.Abstraction.Data.OutlineTracers | the outline tracers by name, overridable once for every package that traces glyphs
Idrak.Abstraction.Data.IFontMaker | how labelled glyphs become a font, for every package that makes fonts from images: Imaging's traced maker today, the command line's font-from (plan 38's F6) and an app's or a plug-in's own maker over the library's next
Idrak.Abstraction.Data.FontMakers | the font makers by name, overridable once for every package that makes fonts from glyphs
Idrak.Abstraction.Data.ITextShaper | how text becomes positioned glyphs, per script, for every package that draws text (Imaging draws, Text's synthetic pages lay out, Vision makes text samples); a script's shaper is registered once for all of them
Idrak.Abstraction.Data.TextShapers | the shapers by script, overridable once for every package that draws text
Idrak.Abstraction.Cluster.IFailureModel | which faults a run injects (slow, dropped, lost links, partitions, late joins), for every package that runs ranks: the simulator (Idrak.Cluster) and, from C5, Idrak.Network's real transports under test, so a seeded fault plan replays the same on both
Idrak.Abstraction.Cluster.FailureModels | the failure models by name, overridable once (IDRAK_CLUSTER_FAILURES) for every package that runs ranks
Idrak.Abstraction.Reinforcement.AdvantageEstimators | the estimators by name, overridable once for every package that trains a policy
Idrak.Abstraction.Reinforcement.PolicyLosses | the policy losses by name, overridable once for every package whose policy trains with them
Idrak.Abstraction.Reinforcement.RewardFunctions | the rewards by name for every package that scores text (Idrak.Text's, R3; the coding plug-in's, R4)
Idrak.Abstraction.CommandSandboxes | the sandboxes by name, chosen once (IDRAK_SANDBOX) for every package that runs a command a model asked for
Idrak.Abstraction.Generation.ITokenSamplerKind | the sampler kind every token-generating package takes from TokenSamplers, and the one an app or a plug-in registers over the library's
Idrak.Abstraction.Formats.IBFloat16TensorStore | a tensor store's optional 16-bit read, beside ITensorStore: any package's store (a format plug-in's, a renaming view) offers it and any package that packs weights reads it
Idrak.Abstraction.Generation.ChatTemplate | the base of a chat template (IChatTemplate) for any package that reads one: Text's Jinja templates today, a family plug-in's or an app's own tomorrow
Idrak.Abstraction.Generation.IPackedFormat | a packed weight format any package may add (a plug-in's own quantization) and every package that builds layers packs with, by name
Idrak.Abstraction.Generation.PackedWeightFormats | the packed weight formats by name, overridable once for every package that packs weights
Idrak.Abstraction.Generation.ToolCallFormats | the tool-call formats by name, beside ChatTemplates: a family plug-in registers its own once for every package that parses a chat model's output
Idrak.Abstraction.Formats.IOnnxRuntimeLoader | how a host runs an ONNX model outside Idrak's own import (the tool's onnx check, an app comparing outputs) without referencing the runtime's package; Idrak.Onnx.Runtime registers ONNX Runtime, and any package may register another runtime
Idrak.Abstraction.Formats.OnnxRuntimeLoaders | the ONNX runtimes by name, filled through LibraryDefaults when Idrak.Onnx.Runtime ships (or a host loads it with -P), so a host finds one with no reference to it
Idrak.Abstraction.Modules.IPeftAdapter | an adapter in peft's layout beside ILinearAdapter: the built-in LoRA and DoRA adapters (Idrak.Abstraction) implement it, and any package's adapter kind (a plug-in's own) is saved and loaded through it by every package that writes PEFT folders
Idrak.Abstraction.Generation.IOwnedPositionBias | a position bias with parameters of its own, beside IAttentionPositionBias: AttentionPositionBias (Idrak.Abstraction) implements it, and any package's attention layer that owns a bias lists its module as a child
Idrak.Abstraction.Plugins.IPluginPackageCatalog | which plug-in package holds a name a registry refuses: any package's registry names it in its refusal (PretrainedArchitectures first; VisionFamilies, SpeechFamilies, EnvironmentKinds and the rest as their packages declare names), and an app adds a catalog of packages it does not ship
Idrak.Abstraction.Plugins.PluginPackageCatalogs | the catalogs by name, the library's (the declarations of the packages the program has) first, asked by every package's refusals
Idrak.Abstraction.Text.TextHabits | the handwriting habits by name for every package that draws text (Text's synthetic pages today, Vision's text samples tomorrow); rule sets register from the package that ships them, the engine (RuleTextHabits) and PageStyle.Habits live beside it
Idrak.Abstraction.Generation.IRowPackedFormat | how a packed format packs a checkpoint's weights from their output rows a block at a time (no float32 copy of the matrix, no transposition), beside IPackedFormat: every package that loads weights into a packed format (text, vision, audio models) packs through it
Idrak.Abstraction.Data.IDocumentFormat | a document format any package or plug-in reads and every package opens documents through (plan 28, decision 1): PDF is Idrak.Data's, Office comes as a plug-in, an app may register its own
Idrak.Abstraction.Data.DocumentFormats | the document formats by name, chosen by a file's first bytes, overridable once for every package that opens documents (Idrak.Data registers pdf; the Office plug-in to come registers its own)
Idrak.Abstraction.Data.IDocumentTextLayout | how any format's runs become lines and text (plan 28, C10): the library's lines and content layouts live beside it, every format arranges through it (PDF in Idrak.Data, the Office plug-in to come), and an app may register its own
Idrak.Abstraction.Data.DocumentTextLayouts | the text layouts by name, overridable once for every format that arranges a page's runs into lines (DocumentOptions.Layout names one)
Idrak.Abstraction.Data.ISignatureService | how a signature reaches a timestamp authority, a revocation list's address or an OCSP responder, for every package that signs or checks documents (plan 28, D12): PDF in Idrak.Data today, the Office plug-in to come; an app reaches them its own way (a proxy, credentials, an offline cache) by registering one under the scheme
Idrak.Abstraction.Data.SignatureServices | the signature services by address scheme, overridable once for every package that signs or checks documents (Idrak.Data registers http and https)
